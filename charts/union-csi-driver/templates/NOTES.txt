{{ include "union-csi-driver.fullname" . }} is installed with the {{ include "union-csi-driver.backend" . }} backend.

Pods request a merged mount by naming their own sibling volumes:

  volumes:
    - name: merged
      csi:
        driver: {{ include "union-csi-driver.driverName" . }}
        volumeAttributes:
          sourceVolumes: "data=RW,archive=RO"

sourceVolumes entries are volume names from the same pod, leftmost wins on lookup.
Each source volume must also be listed in some container's volumeMounts: kubelet
only sets up volumes a container mounts.
{{- if eq (include "union-csi-driver.backend" .) "overlay" }}
The overlay backend accepts at most one =RW entry and it must be listed first: the
kernel always stacks the single upperdir on top. Its merged content lives in
<volume>/.union-csi/upper, so data already at the root of the RW volume is not
part of the merge.
{{- else }}
Any number of entries may be =RW; category.create decides which one a new file
lands on. mergerfs has no copy-on-write: it cannot express read-only lowers plus a
writable top layer.
{{- end }}
